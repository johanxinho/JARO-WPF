## Dictamen

El repositorio contiene una **integración real de WireGuardKit en el ciclo de vida del Packet Tunnel**, no una implementación de red ficticia: `JaroWireGuardEngine` construye una `TunnelConfiguration`, crea `WireGuardAdapter(with: packetTunnelProvider)` y espera el callback de `start`. El release upstream fijado por CI instala `NEPacketTunnelNetworkSettings`, encuentra el descriptor `utun` y llama al backend `wg-go` (`wgTurnOn`). Esto no prueba que un túnel JARO haya transferido tráfico en un iPhone: faltan una firma con entitlement autorizado, un peer propio operativo y una prueba física con handshake, tráfico bidireccional y egress.

JARO **no implementa su propio bucle Swift de `packetFlow.readPackets`/`writePackets`**. WireGuardKit tampoco usa esas llamadas: el adapter upstream trabaja mediante el descriptor `utun` y su backend. Por tanto, WireGuard depende de esa implementación upstream integrada; SSH no. SSH ofrece una sesión autenticada y forwarding TCP `direct-tcpip` para SOCKS5/HTTP CONNECT. En iOS se configura un proxy HTTP/HTTPS local, pero no se procesan paquetes IP y se rechazan rutas para SSH: **no es un túnel IP/VPN de sistema**.

Se corrigió el teardown/cancelación del provider y la selección explícita del Keychain App Group. Se verificó que los ajustes compartidos deben usar literalmente `group.com.jarocomplements.jarowpf`: Apple permite usar un App Group como Keychain access group sin anteponer el Team ID; el propio Keychain denegará la operación si la firma no incluye la membresía adecuada. Se eliminaron entitlements `keychain-access-groups` prefijados redundantes.

## Correcciones aplicadas en esta fase

1. `stopTunnel` marca el lifecycle como detenido, cancela y espera start/reconnect pendientes, frena el monitor de path, detiene los engines y retira explícitamente los network settings antes de completar el stop.
2. `startTunnel` conserva la tarea de arranque, comprueba cancelación antes de publicar éxito y ejecuta teardown si el arranque falla o se cancela.
3. Una pérdida de path ahora falla cerrado: invalida capacidades, detiene transports y elimina settings/rutas antes de intentar recuperación cuando vuelva una ruta permitida.
4. Las tareas de recuperación respetan cancelación durante backoff y antes de publicar estados de fallo; stop espera la recuperación en curso antes del teardown final.
5. El vault especifica el Keychain access group compartido exacto `group.com.jarocomplements.jarowpf`, valida que referencias de perfil y PSK pertenezcan al App Group esperado y ya no ignora fallos al borrar un ítem previo.
6. Se quitaron entitlements `keychain-access-groups` con prefijo de equipo redundantes: para App Groups, Apple documenta el identificador literal como grupo válido de Keychain. La capacidad App Groups se mantiene en los targets Full/Standalone/PacketTunnel.
7. Se añadieron XCTest para resolver el grupo correcto/rechazar grupos erróneos, y tests Python de contratos para lifecycle, ausencia de packetFlow ficticio y uso del App Group.

## Firma e instalación para Linux Mint + iPhone 12 + presupuesto 0 COP

- **Full/Packet Tunnel:** el entitlement requerido es `com.apple.developer.networking.networkextension` con `packet-tunnel-provider`; app y extensión deben tener App IDs/Bundle IDs, provisioning profiles que correspondan a esos entitlements, capacidad App Groups común y firma válida del mismo equipo. El iPhone debe estar registrado como dispositivo Development. Un `.ipa` unsigned de Actions no se instala directamente.
- La tabla oficial de Apple indica que **App Groups** está disponible también en Apple Developer gratuito, pero **Network extensions** no está disponible en esa columna gratuita. Personal VPN es otra capacidad y no sustituye `packet-tunnel-provider`. Por ello una Personal Team gratuita no basta para firmar/instalar la variante Full con Packet Tunnel.
- Apple publica el Apple Developer Program a **USD 99 por año** (o moneda local donde aplique). Fee waiver requiere una persona jurídica nonprofit, institución educativa acreditada o entidad gubernamental; Apple excluye individuos, propietarios únicos y negocios de una sola persona. No es una ruta aplicable por el mero hecho de tener un proyecto o marca.
- Ruta legítima a coste personal cero para **Full**: que una organización ya inscrita y habilitada para Network Extensions acepte incorporar al desarrollador y provisionar ambos targets, o que una organización elegible obtenga/aporte el fee waiver; en ambos casos hace falta autorización del titular del equipo. Aun así hace falta acceso a un Mac/Xcode para registrar el dispositivo y firmar/probar, aunque el build unsigned se pueda producir en GitHub Actions.
- Ruta de cero COP potencial para **Standalone** (proxy, sin VPN del sistema): usar Apple Personal Team, un iPhone registrado y acceso prestado a un Mac/Xcode; perfiles gratuitos vencen a los 7 días y hay que reinstalar/reprovisionar. En esa variante no se incrusta PacketTunnel ni se obtiene una VPN IP. Linux Mint solo no ejecuta Xcode ni firma la app de iOS por sí mismo.
- No recomiendo certificados/perfiles de terceros, perfiles filtrados, revender cuentas ni “sideload signing” que prometa el entitlement: no otorgan legalmente el entitlement de Network Extension al equipo.
